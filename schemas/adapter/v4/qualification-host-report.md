# Draft Stage 2a report and Q completion successor

This source-only draft responds to [Platform PDR-0102](https://github.com/true-line/agent-bot-platform/blob/main/docs/04-decisions/PDR-0102-protected-adapter-qualification.md) and [DRIFT-027](https://github.com/true-line/agent-bot-platform/blob/main/docs/00-governance/drift-register.md). It is a proposed exact-byte interface for review. It supplies no physical result, signed release attestation, protected launch authority, or positive qualification. The existing adapter/v3 report and fixed `agent-bot/qualification-host-report/v3` purpose remain unchanged and fail closed for acceptance.

## Proposed canonical bytes and signing

The [report](qualification-host-report.schema.json) is RFC 8785 JCS UTF-8 with no BOM, newline, duplicate keys, or unreviewed fields. Its `schema_version` is 4. The fixed domain-separated host purpose for this successor is `agent-bot/qualification-host-report/v4`; the [seven-field envelope](qualification-host-signature.schema.json) carries the exact report bytes as unpadded base64url, their `sha256:` digest, host and signer IDs, and the raw 64-byte P-256 ES256 signature. The signing preimage is ASCII purpose, one zero byte, then the exact canonical report bytes, hashed with SHA-256. A v3 purpose or any other string must refuse. The vector has a real deterministic ES256 signature from a fixture-only P-256 key. That key is not an owner-designated Secure Enclave signer and grants no host authority.

The report carries a complete profile-specific `machine/v3` measurement binding. Protected uses the H/R/B `measurement-binding` shape; cooperative uses the H/R/HQ-broker binding from the released `brokered-b` reservation. Each `run_evidence.q_session` has exactly three distinct immutable `{uri,sha256}` refs: `framed_wire`, `frame_index_envelope`, and `clean_eof_envelope`. The signed Q index purpose remains `agent-bot/stage2a-q-frame-index/v1`; the signed EOF purpose remains `agent-bot/stage2a-q-finished-eof/v1`. Each digest names the *whole* canonical local blob, including the signed envelope. The existing raw Q frame and signed-index/EOF size limits still apply. A verifier resolves all three local blobs and checks their exact bytes, signatures, frame order, raw hashes, reservation digest, clean EOF and no trailing bytes before considering a report.

Protected `run_evidence` requires `reservation`, `finalization`, `execution_completion`, `challenge_sha256`, and `q_session`. It requires the protected bridge and T01/T02/T03 gates and forbids cooperative B assignment, publish order, and publication outcome. Cooperative requires `reservation`, `bridge_assignment`, `cooperative_publish_order`, `cooperative_publish_outcome`, `cooperative_watched_request`, `execution_completion`, `challenge_sha256`, and `q_session`; it requires only T21, forbids the protected bridge and finalization, and its reservation must select released `brokered-b`. The report also references exact watched request bytes, which the offline verifier must hash and compare with the signed outcome while checking the request device, inode, birth time, secure-admin owner UID, R group GID, and mode observed from the same open file descriptor against the signed reservation and installed plan. The A-signed publish order records the one-use B grant and authenticated H/Comms bind and relay status before watched publication. A distinct A-signed publish outcome must record the exact watched request digest, its same-open-FD inode identity, the signed order digest, and the signed `publication_mode: direct` for the sole post-rename signer. Read-only recovery verifies the existing direct outcome and does not mint a new publication claim. The synthetic vectors are source-only; they cannot prove live B-before-R order or confer T21 credit.

## Pre-sign completion and offline join

The proposed [completion payload](../../machine/v2/stage2a-execution-completion-payload.schema.json) has schema version 2 and a separate [A-signed envelope](../../machine/v2/stage2a-signed-execution-completion.schema.json) with purpose `agent-bot/stage2a-execution-completion/v2`. Its exact fields bind host, installation, Soul, start, launch, cohort, profile, reservation, challenge, complete measurement binding and the three Q blob digests. Protected completion requires `finalization_sha256` and forbids B fields; cooperative completion requires `bridge_assignment_sha256`, `cooperative_publish_order_sha256`, and `cooperative_publish_outcome_sha256` and forbids protected finalization. The `report_candidate_sha256` is the canonical report with only `run_evidence.execution_completion` omitted. The report then references the entire signed completion envelope. The proposed [post-sign commitment payload](../../machine/v2/stage2a-report-commitment-payload.schema.json) and [A-signed envelope](../../machine/v2/stage2a-signed-report-commitment.schema.json) use separate purpose `agent-bot/stage2a-report-commitment/v2`. They bind the entire raw canonical host ES256 envelope digest, report payload digest, signed pre-sign completion envelope digest, designated host and signer IDs, profile, installation/Soul/start/launch/cohort, and a commitment time after report recording. The release Statement must reference the exact signed commitment envelope as its completed run. The public release verifier remains closed until a Machine producer and physical traversal implement this successor.

A separate [direct Comms T21 Q vector](../../../fixtures/qualification/v4/q-direct-cooperative-synthetic.json) joins the released `direct-comms` cooperative reservation to A-signed Q wire/index/clean EOF. It requires the Comms broker endpoint and excludes B bridge fields. It is a Q component only; this v4 host report requires `brokered-b` for its cooperative publication path. Neither vector grants T21 credit.

The [synthetic vectors](../../../fixtures/qualification/v4/report-q-join-synthetic.json) use deterministic fixture-only Machine and host keys. They sign the released Q wire/index/EOF purposes for protected and cooperative, re-sign matching `machine/v3` reservations, protected finalization and B assignment, and verify exact report/completion/Q/host signature/post-sign commitment digest joins. Negative vectors refuse missing Q EOF or B publication outcome, a protected finalization in T21, missing signed Q index digest, and wrong completion/host/commitment purposes. Coherently re-signed negatives refuse a finalization for another reservation, an outcome for another order or watched request, mismatched observed inode, publication before authorization or at expiry, and a post-sign commitment for another host envelope or completion. The validator also refuses a changed Q index ref and cross-profile Q replay. These vectors assert contract relationships, not installed bytes, an owner-designated Secure Enclave signer, approved host policy, authenticated B order and publication outcome, raw ACP/OS captures, or T01/T02/T03/T21 results.

The offline acceptance path must still authenticate the independently reviewed owner root and owner-signed designated-host policy, enforce revocation snapshot age **≤3,600 seconds** (future or missing refuses), verify release workflow signing-time proof, and compare released adapter, runner, HQ-started Soul, host, installed launch inputs, Q kernel identity and ordered argv, and physical gate artifacts. This draft enables none of those positive launch or release paths.

The draft [B order payload](../../machine/v3/soul-cooperative-publish-order-payload.schema.json) and [signed envelope](../../machine/v3/soul-cooperative-publish-signed-order.schema.json) pin the current Machine producer purpose `agent-bot/soul-cooperative-publish-order/v3`. The separate [publication outcome payload](../../machine/v3/soul-cooperative-publish-outcome-payload.schema.json) and [signed envelope](../../machine/v3/soul-cooperative-publish-signed-outcome.schema.json) use proposed purpose `agent-bot/soul-cooperative-publish-outcome/v3`. The outcome chains the exact signed order envelope, primary and private reservation digests, watched request bytes and positive decimal inode identity, start/launch, publication time, expiry, and signed direct publication mode. Read-only recovery can return the existing direct outcome; it cannot turn intent into a recovered publication claim. Its final wire and witnessed inode semantics require Machine producer alignment before release.
