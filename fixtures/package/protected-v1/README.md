# Protected-content interoperability vectors

Run `python scripts/validate.py` from the repository root. Read fixture references relative to `fixtures/` and use each referenced envelope's `input`. The encrypted selection starts from Appendix C instance A. The other Appendix C identity has the same definition revision and is a negative identity-binding control. [Core vectors](../appendix-c/README.md) · [Wire records and byte rules](../../../schemas/package/protected-v1/README.md)

**Crypto.** In [crypto.json](crypto.json), the referenced protected envelope is the simulated package. The plaintext expected manifest and externally supplied synthetic keys, journal trust and decisions are reader test inputs. Process each case independently. For locked inspection return the exact status and metadata projection. For open, unwrap and authenticate before reading the manifest. An optional byte flip XORs the specified ciphertext byte with 1. For rewrap, compare the two changed header fields with the published recipient-B header and independently open that recipient's envelope. Recovery selects that same header. For restriction-only tests, replace the listed fields of the statement or expected checkpoint, retaining the published signature. For logical-manifest tests, omit the specified source or replace its fields after authenticated decoding. Identity index 0 is A, index 1 is B.

**Policy.** In [scenarios.json](scenarios.json), initialize a fresh host and ledger for each case. Apply case fields over host defaults. The known epoch and held set are the receiver's record of the imported journal. Local holds are a separate overlay. Authenticate the manifest and reconcile its restriction checkpoint before processing steps. `restore` reports that reconciliation result. Each named grant replaces the listed top-level fields of the base grant. Host time and request defaults apply to each step, then its explicit fields take precedence. The peer represents the authenticated transport peer. The credential selector refers to a verified host grant. A recovery selector requests use of the external decision. A case can replace fields of the host-resolved credential binding before the first request.

Apply steps in order. Two sessions reserving concurrently use a single serialized ledger order, shown by the steps. A reload reopens the persisted ledger between steps. A receipt reserves the full selected source's decoded byte length. Compare each decision to `expected` and the total reserved bytes to `expected_spent` when present. Results and labels describe fixture decisions. They do not allocate broker wire error codes.

| Decision stage | Fixture outcomes |
| --- | --- |
| Public inspection and external custody | `metadata-only`, `custody-unavailable`, `credential-binding-mismatch`, `unwrap-failed`, `authentication-failed`, `recovery-unavailable`, `rewrap-denied`, `same-logical-content` |
| Checkpoint and identity | `checkpoint-unauthenticated`, `checkpoint-binding-mismatch`, `identity-binding-mismatch`, `source-binding-mismatch`, `selection-binding-mismatch`, `restored`, `checkpoint-stale`, `checkpoint-conflict` |
| Grant and holds | `grant-revoked`, `grant-expired`, `grant-scope-mismatch`, `operation-denied`, `independent-authority-required`, `version-held`, `freshness-unknown`, `held`, `released` |
| Output reservation | `output-limit`, `receipt-already-used`, `budget-exhausted`, `reserved-delivery-unknown`, `allowed` |

For policy requests, public inspection is always available. Check restore conflicts, credential availability, revocation, expiry, grant bindings and operation. Check independent review authority for a restriction decision and effective holds for other operations, then freshness, transitive grant scope and output reservations. A refusal never debits the ledger. A reservation with uncertain delivery remains charged.
